# Report Serializer Skill

## When to Use

Invoke this skill as the final step in every audit pipeline, after all other
skills have completed. Use it to:

- Merge findings from all upstream skills into a single validated report.
- Remove duplicate finding IDs.
- Sort findings by severity (critical → high → medium → low).
- Compute the AI Readiness Score.
- Validate the output against the JSON Schema defined in
  `skills/audit-orchestrator/references/audit_report_schema.json`.
- Emit the final JSON report to stdout.

## Inputs

| Field              | Type        | Required | Description                              |
|--------------------|-------------|----------|------------------------------------------|
| `url`              | string      | Yes      | Audited URL                              |
| `all_findings`     | list[dict]  | Yes      | Merged findings from all skill results   |
| `metadata`         | dict        | No       | Audit run metadata (timestamp, duration) |
| `layer3_contract`  | dict        | No       | Corroboration data for report context    |

## Procedure

### Step 1 — Deduplication

Remove findings with duplicate `id` fields. When duplicates exist, keep the
one with higher severity (lower severity_order value).

```python
SEVERITY_ORDER = {"critical": 0, "high": 1, "medium": 2, "low": 3, "info": 4}
```

### Step 2 — Severity Sort

Sort the deduplicated findings list:
```
findings.sort(key=lambda f: SEVERITY_ORDER.get(f["severity"], 99))
```

### Step 3 — AI Readiness Score

```
W_critical = 20, W_high = 8, W_medium = 3, W_low = 1

penalty = sum(W_severity[f.severity] for f in findings if f.type != "proactive")
score = max(0, 100 - penalty)
```

Score bands:
- 80–100: `"Excellent"` — AI-ready
- 60–79: `"Good"` — minor improvements needed
- 40–59: `"Fair"` — significant gaps
- 0–39: `"Poor"` — critical barriers to AI discoverability

### Step 4 — Schema Validation

Validate the assembled report against
`skills/audit-orchestrator/references/audit_report_schema.json`.

Required top-level fields:
```
schema_version, audit_id, url, timestamp, duration_seconds,
ai_readiness_score, score_band, findings
```

Each finding requires:
```
id, title, severity, type, evidence, suggested_action, check_ref
```

If validation fails: emit a WARNING in the report's `warnings` array (do not
crash; emit the best-effort report).

### Step 5 — Output Assembly

```json
{
  "schema_version": "2.0.0",
  "audit_id": "<uuid4>",
  "url": "<audited_url>",
  "timestamp": "<ISO-8601>",
  "duration_seconds": <float>,
  "ai_readiness_score": <int 0-100>,
  "score_band": "<Excellent|Good|Fair|Poor>",
  "findings": [ ... ],
  "layer3_summary": { ... },
  "warnings": [ ... ]
}
```

## Output

Final JSON report on stdout. If `--format markdown` is passed as an argument,
also emit a human-readable Markdown summary with:
- Score and band prominently displayed
- Top 5 critical/high findings as bullet points with suggested actions
- A "What to fix first" prioritised checklist

The `findings` array MUST NEVER be empty. If no findings were generated by
upstream skills, emit a proactive finding indicating that all checks passed.
